# CafeWiFi 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 Windows 版、支援多品牌的咖啡廳 Wi-Fi 自動連線系統匣 App（功能和 louisa-wifi 對等）。

**Architecture:** 單一 WinForms 專案，分成 `Core`（純邏輯，有完整單元測試）、`Platform`（Windows API 的薄包裝，透過介面隔開）、`App`（流程和 UI）三層。品牌資料以 JSON 內嵌在 exe 中。統計視窗使用 WebView2 加上內嵌的 HTML。

**Tech Stack:** .NET 8、WinForms、ManagedNativeWifi、Microsoft.Web.WebView2、WinRT Geolocation、xUnit、Python 3（抓取腳本）

**Spec:** `docs/superpowers/specs/2026-10-16-cafewifi-design.md`

## Global Constraints

- TFM：`net8.0-windows10.0.19041.0`；發布方式：`win-x64`、self-contained、單一檔案，輸出 `CafeWiFi.exe`，打包成 `CafeWiFi-win-x64.zip`。
- 資料夾：設定與資料放在 `%APPDATA%\CafeWiFi\`，日誌放在 `%LOCALAPPDATA%\CafeWiFi\CafeWiFi.log`。
- StoreKey 格式為 `"<brandId>/<storeName>"`；查不到門市時用 `"<brandId>/未知門市"`。
- 所有 UI 文字使用繁體中文，用詞和原版一致（spec 第 5 節和第 7 節）。
- 時間參數：自動檢查每 15 秒；自己連線後 15 秒內忽略觸發（quiet）；失敗後 snooze 600 秒；每組密碼連線逾時 20 秒；掃描最多等 4 秒；連線檢查逾時 3 秒；Tracker 每 60 秒；更新每 6 小時檢查。
- 最近門市：5 km 內最多 3 家；選單顯示最近 6 家；學習時只記訊號強於 -75 dBm 的 BSSID。
- 所有 JSON 先寫 `.tmp` 再取代；檔案損毀時改名為 `.bad`，並當作空資料處理。

## Review Focus

1. 沒有座標的門市（lat/lng = 0）不能出現在任何「最近門市」結果中，但仍要出現在「所有門市」裡。→ 由 Task 2 的 `Nearest_SkipsStoresWithoutCoordinates` 測試。
2. `learned.json`、`usage.json`、`settings.json` 損毀或內容是空的時候，App 要能正常啟動，並把壞掉的檔案保留成 `.bad`。→ 由 Task 3 的 `Load_CorruptFile_ReturnsEmptyAndKeepsBad` 測試。
3. 沒有無線網卡、Wi-Fi 關閉、WLAN 服務沒啟動時，不能崩潰，只更新狀態文字。→ 由 Task 6 的 `Auto_NoInterface_DoesNothing` 和 `Manual_NoInterface_ReportsFailure` 測試。
4. 使用者輸入的密碼含有 XML 特殊字元（`& < > " '`）時，設定檔 XML 要正確跳脫。→ 由 Task 5 的 `Build_EscapesXmlSpecialCharacters` 測試。
5. 日期邊界：今天是星期日時，方格要從星期一開始排；「過去一年」要剛好 365 天；跨年的連續天數要正確計算；日期 key 不受系統地區設定影響。→ 由 Task 8 的 `Period_*` 和 `LongestStreak_AcrossYearEnd` 測試。
